# Metatron v1.4.0 — Verification and hardware-qualification handoff

## Scope

v1.4.0 closes the remaining *implementation* gaps identified in the v1.3 re-audit. Hardware-dependent proof still has to execute on the target Windows machine; the package now contains a concrete gate for every previously pending item instead of a placeholder.

## Previously pending → v1.4 implementation

| Previous item | v1.4 implementation/gate |
|---|---|
| Windows PowerShell diagnostics execution | `Test-PowerShellScripts.ps1` parses every PS1 and runs a live process metrics smoke test. |
| Native Rust/Tauri build | Windows CI now performs `cargo fmt`, `cargo check`, full `Build-Windows.ps1`, and installer artifact verification. |
| Floating orb visibility/positioning | Rust startup positions the orb on the primary monitor using Tauri monitor APIs; `Test-OrbWindow.ps1` verifies a visible on-screen native window. |
| Real Intel NPU inference | `Verify-OpenVINODevices.py` explicitly compiles and executes a static graph on NPU using OpenVINO's device API; existing WinML verifier remains for application-model placement proof. |
| Intel Arc GPU fallback | Same verifier independently compiles/executes on GPU; application route still uses explicit NPU→GPU→CPU policy. |
| CPU fallback | Same verifier proves CPU execution; existing route/fault-injection tests cover fallback ordering. |
| Microphone/STT integration | `Test-WindowsAudio.py` opens the default microphone and captures real samples; `Invoke-EZSTTQualification.ps1` invokes the pinned upstream EZSTT protocol/e2e/focus/restart tests. |
| TTS playback/interruption | `Test-WindowsTTSInterrupt.py` synthesizes through Windows SAPI, plays via the same Windows `winsound` mechanism, and verifies cancellation completes promptly. Kokoro benchmark remains available when assets are configured. |
| Full-system memory qualification | Existing Windows process-tree/private-WS/commit collector is retained and hardened; incomplete coverage is never converted to zero. |
| Long-duration memory leak test | `Measure-MetatronSoak.ps1` + `Analyze-Soak.py` calculate peak, quartile drift and linear growth MiB/hour. |
| Installer/signing verification | `Verify-WindowsArtifacts.ps1` inventories MSI/EXE signatures; `Sign-Windows.ps1` signs and then verifies with `signtool /pa`. |

## One-command target-machine gate

```powershell
.\scripts\Invoke-MetatronReleaseClosure.ps1 -Python <path-to-test-venv>
```

The release-closure wrapper requires Metatron↔EZSTT placement and Kokoro, auto-runs the pinned EZSTT protocol/focus/restart/E2E suite, and defaults to a 60-minute soak. Use `Invoke-MetatronV14Qualification.ps1` directly for narrower diagnostic runs.

For release signing, add `-RequireSigned` after signing the bundle with `Sign-Windows.ps1`.

## Environment boundary

This Linux container has no Windows desktop, PowerShell, Rust/MSVC toolchain, microphone endpoint, Intel NPU or Intel Arc device. Therefore the native gates above are implemented and statically/portably vetted here, but their PASS evidence must be generated on the target Windows machine. The scripts intentionally report SKIP/FAIL rather than manufacturing a hardware PASS when a required runtime/device is unavailable.
